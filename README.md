# Бот мониторинга Реестра казахстанских товаропроизводителей (e-ondiris.gov.kz)

Telegram-бот [@ondiris95bot](https://t.me/ondiris95bot). У каждого пользователя свой список БИН/ИИН.
Бот раз в день проверяет список и пишет **только когда есть изменения**: организация появилась в реестре,
у неё появился или был исключён товар, изменилось наименование.

## Как пользоваться (для пользователя)

Нажмите `/start`. Внизу появится меню:

| Кнопка | Что делает |
|---|---|
| ➕ Добавить БИН | Отправьте один или много БИН в любом виде (через пробел, запятую, `;`, с новой строки, таблицей) или Excel/CSV-файл |
| 🔎 Проверить БИН | Сразу показывает данные из реестра по одному БИН и предлагает добавить его в мониторинг |
| 📋 Мой список | Все ваши БИН с названиями (✅ в реестре, ⏳ пока нет), с постраничным просмотром |
| ➖ Удалить БИН | Удаляет один или несколько БИН |
| 🔄 Проверить сейчас | Проверяет весь ваш список немедленно и присылает итог |
| ⚙️ Настройки | Время автопроверки и включение/выключение уведомлений |

Можно ничего не нажимать: если отправить в чат один БИН, бот покажет по нему данные, а если несколько — добавит их в мониторинг.

Команды: `/start`, `/help`, `/add [БИН…]`, `/check` (весь список) или `/check БИН`, `/list`, `/remove БИН [БИН…]`, `/settings`, `/cancel`.

## Запуск

Бот работает постоянно, поэтому ему нужен сервер или компьютер, включённый круглосуточно.

### Docker (рекомендуется)

```bash
git clone https://github.com/alibiamanzhol/ondiris-bot.git
cd ondiris-bot
cp .env.example .env        # впишите TELEGRAM_BOT_TOKEN
docker compose up -d --build
docker compose logs -f      # журнал
```

База хранится в `./data/bot.db` и не пропадает при перезапуске или пересборке контейнера.

### Без Docker

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите TELEGRAM_BOT_TOKEN
python -m ondiris_bot
```

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather (обязательно) |
| `MONITOR_TIME` | `18:00` | время ежедневной проверки по умолчанию (каждый пользователь может выбрать своё) |
| `TIMEZONE` | `Asia/Almaty` | часовой пояс расписания |
| `ALLOWED_TELEGRAM_USER_IDS` | пусто (доступ всем) | список user_id через запятую; посторонний пользователь увидит свой ID и сможет передать его вам |
| `DB_PATH` | `data/bot.db` | путь к базе SQLite |
| `PORTAL_CONCURRENCY` | `3` | одновременных запросов к порталу |

## Перенос списков из старой версии

Прежняя версия работала через GitHub Actions и хранила списки в `state.json`. При первом запуске бот сам
переносит их в базу (один раз) и молча фиксирует текущее состояние, чтобы не прислать старые данные как новые.

Импорт любого списка конкретному пользователю:

```bash
python -m ondiris_bot import <telegram_user_id> list.xlsx          # или .xls / .csv / .txt
docker compose run --rm bot python -m ondiris_bot import <user_id> /app/data/list.xlsx
```

## Как устроено

| Модуль | Ответственность |
|---|---|
| `ondiris_bot/bot.py` | Telegram: меню, кнопки, команды, файлы, планировщик |
| `ondiris_bot/service.py` | пользовательские сценарии, ежедневный запуск, миграция |
| `ondiris_bot/bins.py` | извлечение и проверка БИН/ИИН из текста, Excel, CSV |
| `ondiris_bot/portal.py` | клиент API реестра (`/awp-api/registry-front?bin_iin=…`) с пагинацией и повторами |
| `ondiris_bot/snapshot.py` | значимое состояние организации и сравнение |
| `ondiris_bot/monitor.py` | цикл мониторинга, отправка уведомлений |
| `ondiris_bot/messages.py` | тексты сообщений |
| `ondiris_bot/storage.py` | SQLite: пользователи, подписки, снимки, очередь уведомлений |

Принципы:

- **Базовое состояние.** При добавлении БИН его текущее состояние фиксируется, и дальше сообщаются только отличия от него.
- **Сравнение.** Сравнивается набор товаров и наименование, а не сырой ответ, поэтому порядок записей и служебные поля не влияют.
- **Ошибки портала.** Ошибка портала (таймаут, 5xx, Cloudflare, не-JSON, неполная пагинация) не считается изменением:
  снимок сохраняется, проверка повторится в следующий раз. Исчезновение организации подтверждается повторным запросом.
- **Без дублей.** Новый снимок и уведомление записываются одной транзакцией в очередь `outbox` с ключом дедупликации,
  поэтому одно и то же изменение не придёт повторно. Если отправка сорвалась, сообщение будет доставлено при следующей попытке.
- **Один запрос на БИН.** Если один БИН отслеживают несколько человек, за цикл он запрашивается один раз,
  а снимки у каждого пользователя свои.
- **Расписание.** Проверка идёт по `Asia/Almaty`, раз в сутки для каждого пользователя. Если бот был выключен
  в 18:00, проверка пройдёт после включения в тот же день.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q
LIVE_PORTAL=1 python -m pytest -q -s tests/test_live_portal.py   # проверка на реальном портале
```

GitHub Actions запускает тесты, включая проверку на реальном портале, при каждом push.
